#2 — Hardcoded timezone → per-course timezone
Before
const timeFormatter = new Intl.DateTimeFormat(
  "en-US", {
    timeZone: "America/Chicago", // hardcoded
  }
);
function formatTime(iso: string) {
  return timeFormatter.format(parseISO(iso));
}
After
const timeFormatterCache = new Map();
function getTimeFormatter(timezone: string) {
  // cached per-timezone
  if (!timeFormatterCache.has(timezone)) {
    timeFormatterCache.set(timezone,
      new Intl.DateTimeFormat("en-US", { timeZone: timezone })
    );
  }
  return timeFormatterCache.get(timezone);
}
function formatTime(iso, timezone = "America/Chicago") {
  return getTimeFormatter(timezone).format(parseISO(iso));
}
// called as: formatTime(slot.start_time, course.timezone)

New Files Added
NEW src/lib/supabase-server.ts

Exports makeSupabaseFetch(key) — the opaque-key header stripping logic, extracted from 3 separate copies that existed in auth-middleware.ts, tee-times.functions.ts, and client.server.ts.

Also exports getPublishableClient() — a module-level cached Supabase client so a new instance isn't created on every server function call.

NEW MIGRATION supabase/migrations/…_atomic_booking_rpc.sql

Creates the book_tee_time(p_tee_time_id, p_user_id, p_players) Postgres function. Uses a single UPDATE … WHERE available_spots >= p_players followed by an INSERT INTO bookings, all inside one transaction.

If the spot count check fails, raises P0001 with "Not enough spots available". Callable only by authenticated role.

NEW MIGRATION supabase/migrations/…_courses_timezone.sql

Adds timezone text NOT NULL DEFAULT 'America/Chicago' to the courses table. Back-fills all existing rows to America/Chicago.

NEW MIGRATION supabase/migrations/…_rolling_tee_times.sql

Creates refresh_tee_times() — deletes stale/future-beyond-7-days slots and re-seeds a rolling 7-day window, idempotently. Runs immediately at migration time.

Schedule this daily (pg_cron or Supabase Edge Function cron) so the app always has current availability. Previously, all slots were seeded once at migration time and expired after a week.

NEW MIGRATION supabase/migrations/…_tee_times_rls_update.sql

Adds an explicit RLS UPDATE policy on tee_times that blocks direct mutations from authenticated clients (USING (false)). All writes must go through the book_tee_time() SECURITY DEFINER RPC which bypasses RLS intentionally.
